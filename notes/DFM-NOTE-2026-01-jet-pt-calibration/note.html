Machine-Learned Jet pT Calibration from Low-Level Detector Information

DFM-NOTE-2026-01 · UTA Detector Foundation Model group (A. Farbin, M. A. Ghaznavi, U. Ghaznavi et al.; analysis assisted by Claude) · August 2026
Repository: github.com/afarbin/DetectorFoundationModel, branch dfm-merge
Abstract

We present a systematic study of machine-learned jet transverse-momentum calibration from low-level detector information, using 620k truth-matched light jets from simulated ttbar events. A shared token encoder over calorimeter cells (with the detector neighbor graph recovered via exact cell matching between two ntuple formats), charged tracks, and reconstructed jet features is trained to regress the per-jet log pT response with a heteroscedastic Gaussian objective. We compare all input combinations, graph versus set encodings of the calorimeter, and self-supervised masked-cell pretraining against from-scratch training. The best configuration (tracks + jet features + cells on the neighbor graph) approximately halves the jet energy resolution relative to the input reconstructed jets (11.9% versus 23.8% inclusive). Detector topology is a measurable inductive bias for cells-only models; combining all modalities requires O(10^5) labeled jets to pay off. A linear probe of the pretrained encoder matches full end-to-end training, demonstrating that the masked-cell pretext learns calibration-relevant representations; label-efficiency gains from pretrained initialization are small but consistent below 10% label fractions.

1. Introduction

This note is the first of three [1,2] documenting the initial physics program of the UTA Detector Foundation Model (DFM) effort, which unifies two previously separate model lines - a calorimeter-cell graph network for topoclustering (M. A. Ghaznavi) and a track-based attention model for event-level b-tagging (U. Ghaznavi) - into a single shared backbone with task-specific heads (the dfm package). Hadronic jet calibration was selected as the first benchmark task following the program review [3]: it is a regression with unambiguous truth, a strong classical baseline (the ATLAS jet energy scale chain [4]), and it exercises every component of the merged architecture.

The target throughout is the per-jet log response y = ln(pTtrue/pTreco); the model predicts (μ, σ) per jet, and the multiplicative correction eμ defines the calibrated jet. The study is organized in gated tiers: dataset QA and no-training baselines (Tier 0), single-input models (Tier 1), input combinations and protocol cross-checks (Tier 2), the full-data matrix (Tier 3), and self-supervised pretraining (Tier 4).

2. Data samples and the cell-matching bridge

Two ntuple formats enter the study. The 5D ntuples (17 files, 340k simulated ttbar events, ~6 GB each) provide tracks, jets, truth information, and a thinned calorimeter cell record; we measured the thinning empirically to be a per-cell threshold E > 0.5 GeV and E > 2σnoise, positive energies only. The Calo ntuples provide all 187,652 calorimeter cells per event in fixed hash order with the full detector neighbor list, plus topocluster associations.

The two formats contain different event samples, but their cell centres are bit-identical: an exact nearest-neighbour match in (x, y, z) within sampling layer (library cell_matching.py) identifies every 5D cell with its calorimeter hash position with zero mismatches in 146k jets tested, and a persistent Cell-ID lookup makes this free after warm-up. This bridge transfers the detector neighbor graph onto the thinned 5D cells - enabling the graph-encoding comparisons of this note - and connects the pretraining corpus (Calo format) to the calibration data (5D format).

The thinned cell record retains 75.0% of the energy of the cells in jets (pT > 20 GeV; per-jet median 63%, 10th-90th percentile 32-85%, rising with jet energy), with strong layer dependence (EMB1/EMB3 ~33%, Tile A/BC 81-86%). Cells-only results below are therefore lower bounds on full-cell performance. Large negative deposits in the forward calorimeter (FCAL pileup noise reaches tens of GeV per cell, and out-of-time pileup produces negative event sums) are handled with a cell-level |E| < 100 GeV cut rather than event vetoes; jet cones are central and unaffected.

3. Per-jet dataset

One sample per truth-matched light jet (HadronConeExclTruthLabelID = 0): pTtrue > 20 GeV, recomputed ΔR(reco, truth) < 0.3, |η| < 2.5, duplicate-truth-match removal. Isolation (no reco jet with pT > 15 GeV within ΔR < 0.8; no other truth match within ΔR < 1.0) is stored as a flag: training uses isolated jets, and both populations are evaluated separately. Per jet we store: 6 jet features; all ghost-associated tracks with 18 features each (kinematics, impact-parameter significances computed from the track covariances, hit content); all cone (ΔR < 0.4) cells with the 7-feature calorimeter schema and their matched neighbor subgraph; and metadata. Splits are by file: 13 train / 2 validation / 2 test files = 181k isolated training jets of 620k total. Training weights flatten the pTtrue spectrum over 20-250 GeV (capped at the 99th percentile).

4. Methodology

4.1 Model

All configurations are assemblies of the shared dfm backbone: per-modality input projections with type embeddings; local mixing per modality (SAGE-style convolution over the fixed calorimeter neighbor subgraph for cells; masked k-NN EdgeConv in (η, sinφ, cosφ) for tracks); a shared mask-aware induced-set-attention (ISAB) stack, cross-modality where multiple inputs are present; masked-mean global pooling; and a head MLP emitting (μ, logσ2). Jet features, when enabled, join at the head. Models are ~1M parameters (dim 128, 2 local + 2 global layers) - deliberately small, as the study compares information content, not capacity.

4.2 Training and metrics

Loss: Huber warm-up (5 epochs) then heteroscedastic Gaussian NLL; AdamW with cosine schedule; early stopping on validation NLL; 3 seeds per configuration. Metrics per (pTtrue, |η|, φ) bin on the corrected response rcorr = (pTreco/pTtrue)·eμ: JES closure = median(rcorr) (target ±1-2%); JER = (q75−q25)/1.349 ÷ median (Gaussian-equivalent robust width); pull = (y−μ)/σ (unit-normal if σ is calibrated). Baselines: B0 = the ntuple's calibrated jets after our cuts; B1 = one global median correction; B2 = the jet-features-only model.

5.2 Tiers 1-2 - single inputs and combinations (4-file dataset)

On the initial 4-file dataset (146k jets): the calorimeter neighbor graph beats a set encoding of the same cells on every metric (ΔNLL ≈ 0.11); constituent inputs (tracks or cells) each cut JER by ~30% while the jet 4-vector alone improves resolution by exactly nothing (it can only re-centre); tracks and cells combine (TC 0.147 versus 0.157/0.158 alone); and a median-targeting (MAE) training variant confirmed a ~2% mean-versus-median estimator offset in the NLL closure, fixable by protocol. μ-conditioning changed nothing, isolating the jet-feature advantage as thinned-away constituent information rather than pileup conditioning.

5.3 Tier 3 - the full-data matrix

Scaling to all 17 files (620k jets, 181k isolated training jets) improved every configuration and reversed one Tier-2 conclusion: with sufficient statistics, cells contribute on top of tracks + jet features (Table 1, Fig. 5). 5.4 Tier 4 - self-supervised pretraining

Masked-cell pretraining (cluster masking at ratio 0.15, reconstructing the scaled cell significance, with a mask-indicator channel making pretrained and finetuned encoders weight-compatible) was performed on all three processed calorimeter corpora (ttbar + single-pion + hh→bbττ, 14.4k events); scaling the corpus 16× improved validation reconstruction from 0.507 to 0.347. Transfer results (Table 2, Figs. 7-8): finetuning from the pretrained encoder neither helps nor hurts at full labels; the linear probe - frozen encoder, trained head - matches full end-to-end training (JER 0.157 vs 0.158) with the best closure of its family; and pretrained initialization is consistently ~1-2% relatively better at 1% and 10% label fractions.

6. Systematic considerations and known limitations

  • Cell thinning: the 5D subset carries 75% of jet cell energy with a fluctuating jet-by-jet deficit; cells-only numbers are lower bounds, and the JC-versus-C gap quantifies information the thinning discarded.
  • Truth-match purity: the stored match-quality ΔR branch is unfilled; purity rests on the recomputed ΔR < 0.3 and pTtrue > 20 GeV cuts, validated by the B0 response tightening to a sane core (median 1.065) after cuts.
  • Low-pT closure: no configuration closes the 20-30 GeV bin (spectrum-edge resolution migration); the standard numerical-inversion treatment is the designated fix before any external-facing numbers, together with the MAE/median protocol for the ~2% NLL estimator offset.
  • Sample dependence: single ttbar sample; event-level context learned by the models is legitimate physics but sample-specific - a different-process test sample is required to quantify transfer.
  • Pretraining overlap: event disjointness between the ttbar pretraining corpus and the 5D files is unverifiable (unfilled event numbers); the 3-corpus mix dilutes, and the probe result is immune in interpretation.
  • Isolation: headline numbers are for isolated jets; the measured isolated→non-isolated degradation (e.g. T: JER 0.171 vs 0.158) defines the target for the planned event-level Stage 2.

7. Conclusions

A shared token encoder over thinned calorimeter cells, tracks, and jet features - with the detector neighbor graph recovered by exact cell matching - halves the jet pT resolution of the input reconstruction across 20-400 GeV while closing the scale to a few percent. Detector topology is a real inductive bias for calorimeter-only models; full input combination pays off once O(105) labeled jets are available. The masked-cell pretext demonstrably learns calibration-relevant representations (probe ≈ full training), with small consistent label-efficiency gains at this model scale. These results establish the baseline and the machinery for the flavor-aware studies of [1] and the joint tagging-calibration study of [2].

Appendix A - Operations

The campaign (41 trainings + 2 pretrainings, 4×A30) survived one node freeze requiring an administrator reboot. Root cause: uncapped torch/numpy OpenMP thread pools (56 threads per process, stacked across concurrent jobs starving the scheduler); mitigations now standard: thread caps (OMP_NUM_THREADS=6), niced processes, an alert/pause/kill resource watchdog, SSH connection multiplexing, reboot-proof code and state locations, and re-entrant job queues. A memory diagnostic for a co-located 186 GB training job is documented in reviews/trainer_memory_diagnostic.md.
